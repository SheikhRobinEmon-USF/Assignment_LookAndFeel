Why theme parks

Theme parks were my assigned topic, and it turned out to be a good one. USF sits right next to Busch Gardens Tampa Bay, and Orlando's parks are about an hour and a half up I-4. I approached the site the way I'd approach any product: start with a real user and a real problem.

The user I picked is a parent planning a Florida trip with kids of different heights. Height minimums are spread across dozens of park pages, and finding out at the front of a long line that a child is two inches short ruins the day. So the home page opens with a height checker that shows every ride a rider can board, park by park. The analytics page answers the follow up questions: which parks are busiest, how crowds have changed since 2021, which coasters are fastest and how many rides open up with each inch.

How I built it

I started with the data, because a data site is only as good as its numbers. Attendance comes from the TEA/AECOM Global Experience Index, the standard industry report. I checked every ride's minimum height, speed and opening year against the parks and public ride references. That check caught real changes: Hollywood Rip Ride Rockit closed in August 2025, and Big Thunder Mountain reopened in 2026 with a lower 38 inch minimum. Closed rides are not on the list.

Next I planned four pages around one consistent menu, then built a small design system first: colors, type scale, spacing and components defined once in a single stylesheet. The yellow ruler and the sign colors borrow from the height signs at every ride entrance. The site supports dark mode, reduced motion and phone screens down to 320 pixels wide.

A few decisions shaped the build:

  • No CSS framework. Bootstrap was allowed, but hand written CSS kept the whole stylesheet small and let the site look like its subject instead of a template.
  • A trimmed D3.js build. The charts use D3.js v7. I bundled only the modules the charts need, which cut the library from about 280 KB to 60 KB, and it loads only on the analytics page.
  • One shared data store. The Manage rides page mocks create, read, update and delete operations on a ride list saved in the browser tab. The height checker and the analytics charts read the same list, so a ride added on one page shows up on the others.
  • Accessible by default. Every page has a skip link, visible keyboard focus and labeled form fields. Forms explain exactly what to fix, and every chart has a data table view and colors tested for color blindness.

Technology

Technologies used to build Coaster Coast
HTML5Semantic page structure, native dialog elements for the ride forms, accessible tables and form controls.
CSS3One stylesheet with custom properties, grid and flexbox layouts, a dark theme and responsive table layouts for phones.
JavaScriptPlain JavaScript with no build step. Handles the height checker, the mock CRUD with validation and undo, and the mobile menu.
D3.js v7Bar, line and step charts with tooltips, direct labels and responsive resizing.
Web storagesessionStorage keeps ride edits for the current browser tab, so the CRUD page behaves like a real database without a server.
FontsBricolage Grotesque for headings and Atkinson Hyperlegible for body text, served by Google Fonts.
GitHub PagesHosts the site straight from the repository.
